### D4 デバッグで得たエンジン知見（重要・再利用可）
- **Bellowing Thunder のトラッシュ選択の実フロー**: 攻撃72宣言ログと同じ観測で
  `type=ATTACHED_CARD / context=DISCARD_ENERGY_CARD(26)` の**一括複数選択**(min=0, max=場の対象枚数)が来る。
  `ENERGY/DISCARD_ENERGY(30)` ではない（そちらはコスト支払い等の逐次1枚選択, min=max=1）。
  → greedy素ピロットは[0]=1枚だけ捨てて70点止まりになっていた。
- **エネ誘導なしでは主力ワザが組み上がらない**: 素ピロット30戦で Bellowing の提示は5回/951選択。
  雷+闘(各2枚)がタケルライコに揃わず、両者とも鳥エンジン(Assault Landing/Speed Wing)で殴り合っていた
  ＝ D4 の総当たり30.5%はデッキの短所ではなく「素ピロットでは勝ち筋が存在しない」ため。
- **一方でエネ誘導・出す先の決め打ちは実測でマイナス**（ATTACH+PROMOTE ON: 39.8→45.0→OFF: 47.8%）。
  Bellowing プランを強制するより、エンジン既定の「鳥ビート」の方がこのピロットでは強い。
  実大会プラン（人間用）とAIピロット最適プランは別物、の決定的な実例。
- **MAIN強制の deck 依存性**: 強制なしだとエンジン[0]は Burst Roar 等を選び、LFが揃っても
  Bellowing を一度も使わない。リーサル時のみのMAIN強制（greedy_lethal型）が妥当。
- D3/D4 とも対 kangaskhan はデッキ差で 4.5%/大差 → ライブ投入対象ではなく、戦術実装の演習・知見蓄積として価値。

## プレイブックの学び（どこで効き、どこで壊れるか）
- **効く**: デッキが直線的（D7: 主力に集約・進化元に先置き）で、エンジンの静的順序が知り得ない
  デッキ依存ターゲティング（エネ付け先/出す先）に決め打ちが合う場合 → **+15pt**。
- **壊れる**: 特殊エネの振り分けやモード切替（Kangaskhan: Mist/Spiky/GrowGrass, ガルーラ⇔イワパレス）を
  エンジン既定が既に正しく処理しているデッキに、優先度テーブルの決め打ちを被せた場合 → **−22pt**。
- 敵側の対象選び（KOできる相手>低HP）のみの上書きは**中立**（ローカル解像度では判別不能）。
- 運用則: **プレイブックは ALLY/ENEMY フラグで適用範囲を選び、必ず同一デッキ・素ピロットとの400戦A/Bで検証してから採用**。

## meta_aware の v1 ゲーティング（退化・不採用）
- 仮説: 相手がコントロール/LO系(crustle_lo)なら、リーサルが無くてもテンポ重視で攻撃させる。
- 結果: **対crustle 93.5% → 82% に悪化**（pool 200戦/相手）。head-to-head は非コントロール相手で発火せず 50/50。
- 教訓: greedy_lethal の `[0]`+lethal が既に正着で、そこを無理攻めで上書きすると下がる（713608「強い方針を触ると悪化」と一致）。
- 対応: `ENABLE_TEMPO_GATING=False` で無効化。推定器は毎ターン走らせたまま「より良いゲーティング/探索」の土台として温存。

## greedy_lethal2 の正確打点（中立だが保持）
- 変更: 素点だけでなく、攻撃側タイプ vs 相手の弱点(×2)/抵抗(−30)、Maximum Belt(+50 vs ex/megaEx) を反映した実効打点で lethal 判定。
- 結果: 現デッキ(sample_abomasnow)では **A/B有意差なし**。我々の攻撃タイプ=水で弱点×2が刺さる相手が少なく（Cinderace程度）、Belt+50が勝敗を反転させる場面も稀。
- データ注記: エンジンの `ex` フラグは **megaEx を含まない**（Mega Abomasnow ex は ex=False/megaEx=True）。「ポケモンex」判定は `ex or megaEx` にした。
- 判断: 退化ではなく打点計算は正しくなったので**保持**。弱点/ツールが lethal 計算に効く**強いデッキ(③)でこそ価値が出る**見込み。→ ③のデッキ評価はこの正確打点(greedy_lethal2)を固定 behavior にして行う。

## デッキ総当たり（③, behavior=greedy_lethal2 固定）
`scripts/compare_decks.py` で、ピロットを一定にしたデッキ強度を測定。ホスト提供の
メタデッキ（lucario_ex/dragapult_ex/iono）を追加し **6デッキ総当たり(150戦/ペア)**:

| デッキ | 総合勝率 |
|---|---|
| **sample_abomasnow** | **78.0%** [74.9–80.8] |
| archaludon_cinderace | 59.6% [56.0–63.1] |
| greattusk_crustle_lo | 48.7% [45.1–52.2] |
| lucario_ex | 47.3% [43.8–50.9] |
| dragapult_ex | 39.7% [36.3–43.3] |
| iono | 26.7% [23.6–29.9] |

- **メタ本命 Lucario 等を足しても sample_abomasnow が最強(78%)**（＝現ライブ greedy_lethal のデッキ, 600点）。abomasnow は対 dragapult 84% / 対 crustle 92.7% / 対 iono 86.7% / 対 lucario 66%。
- 理由: Abomasnow は高HP+Belt の脳筋ビートで**スキルフロアが低く**、単純な速攻ピロットで回せる（717697 と一致）。他デッキ（Dragapult分散/Lucario切替/Iono/Crustle制御）は**巧いピロットが要る**ため greedy_lethal2 では活きない。
- **結論: デッキ載せ替えでは強くならない。ボトルネックはデッキではなく "ピロット"**。lever はピロット改善（意思決定）へ移る。

## 相手効果の可視性（Issue #3）と発見した2つのピロット盲点
- **可視性**: `all_card_data()`(特性`skills`+ワザ一覧) と `all_attack()`(威力/コスト/テキスト) により、**判明した相手カードIDから特性・ワザ効果を完全参照できる**。相手モデリングの土台。
- **盲点1: 被ダメ無効特性の見落とし** — Crustle #345 特性=「相手のポケモンexのワザダメージを全て防ぐ」。我々の Mega Abomasnow ex(megaEx) は Crustle に0ダメージだが、greedy_lethal2 はこれを見ずに殴って空振りしうる。出口=非exの Kyogre #721。→ 免疫を考慮した打点/対象選択が必要。
- **盲点2: 効果ダメージの見落とし（重要）** — 主力 Mega Abomasnow ex「Hammer-lanche」は `all_attack` の base damage=0（実威力=捨てた基本水エネ×100 の効果ダメージ）。**素点ベースの lethal 判定は可変/効果ダメージを0とみなす**。多くの現代ワザが該当し、rule-based の打点計算の根本的限界。→ 主要ワザの威力推定（盤面から算出）か、search API での実シミュレーションが必要。
- 含意: 単純ピロットの改善余地はここ（免疫考慮・効果ダメージ推定・シークエンシング）。深追いするなら search か効果モデリング。

## abomasnow_pilot（デッキ特化ピロット・Issue#3対応）
- 追加: Riptide(Kyogre)の正確計算(20×自トラッシュ水エネ, リーサル可)＋被ダメ無効特性の考慮(相手Crustle等にex攻撃を0扱い)。
- **退化と修正**: Hammer-lanche の期待値推定を入れたら、序盤の水エネ密度で推定打点が高くなり確実な Frost Barrier(200)より優先→**自分の山を毎ターン6枚削って自滅(LO)**。vs greedy_lethal 38.2% に退化 → **推定を撤去**（base 0 のまま greedy に委ねる）。撤去後は 50.2%(タイ)/pool 68.7% に回復。
- **重要な学び（評価の解像度限界）**: greedy_lethal2 → abomasnow_pilot と**3連続で「正しいが局所中立」**。原因は**プールの相手が greedy_first 中心で弱く、ピロットの微改善（免疫/効果ダメージ/正確打点）を判別できない**こと（Crustle壁が立たない・Kyogreリーサルが稀）。
  - 対策(a): プールの相手 behavior を強くする（greedy_lethal 等を混ぜる/`compare_decks`のように behavior 固定を上げる）。
  - 対策(b): これらの correctness 改善は**実ラダーで検証**する（弱プールでは測れない robustness 系の改善）。

- **勝ち方の検証（reason probe）**: 勝ちはほぼ全て reason=2（相手山切れ）＝設計通り。

## プライズマッピング（サイド落ち対策）— 2026-07-15
- **実装**: サーチ解決時（ポフィン/ポケパッド/ゴング/ハイパーボール）の `select.deck` は山の
  実物全量 → 「デッキリスト60 − 見えている札 − 山の実物 ＝ サイド落ち」を確定し `_MEM` に保存。
  サイド回収は logs の MOVE_CARD(PRIZE→HAND) で消し込み。`_remaining_in_deck` が確定値になる。
- **落とし穴（実測で発見）**: 解決中のサーチカード自身が手札にもトラッシュにも居ない

## ガントレット巻き戻し判定の修正（deck2 凍結の根本原因）— 2026-07-27
- **症状**: deck2 が再びロールバックループ。**15回**発火し、learner の
  「β×2・lr×0.5」が累積して **β=11.4 / lr=1e-6（下限張り付き）** → clip_frac=0.000＝
  方策が完全凍結。7/22 に教訓として記録しながら判定ロジックを直していなかったのが原因。
- **根本原因（2つ）**:
  1. best が**単発 quick 評価（~700戦・composite ±1.5-2pp のノイズ）の最大値**。たまたま
     高く出た1回（v352 0.9、実力は 0.86-0.87）が恒久的なバーになる。
  2. streak が発火後もリセットされず、**以降の評価すべてで再発火**（1回悪化するたびに
     β×2・lr×0.5 が積み上がる）。
- **修正** (`src/ptcg/ml/rl/gauntlet.py`): 退化判定をロバスト統計2本に置換。
  ①直近6回の中央値 −margin を下回る（最近の自分より落ちた）②歴代上位5件の中央値
  −2×margin を下回る（破滅的退化の絶対床）。履歴4件未満は判定しない。発火後は
  **streak を 0 にリセット**。best のピン留め（＝提出候補の選抜）は従来通り最大値。
- **検証**（deck2 実履歴で単体テスト）: 旧=0.8486 で毎回発火 → 新=発火せず、
  真の退化 0.78 / 破滅 0.70 は正しく検知。
- **復旧**: β 11.378→1.0、lr 1e-6→7e-5、ノイズ盛り best を退避して再ピン、
  両run のガントレットを新コードで再起動。deck1 はロールバック0回で無傷。
- **教訓**: 単発評価の最大値を「基準」にしてはならない（選抜には使ってよい）。
  自動制御の累積項（β・lr）は、発火条件がノイズに晒される限り必ず暴走する。

### 質的情報がどこに入っているかの全体像
1. **one-hot で明示**: option type(18) / area(13) / owner(3) / 対象CardType(7) /

2. **数値スカラー**: HP割合・maxHP/340・被ダメ割合・エネ本数(+0.25飽和)・道具数/2・

3. **ID埋め込みに丸投げ**: カードの正体そのもの → 上記の通り機能していない
4. **どこにも入っていない**: **効果テキスト・特性**。唯一の例外が C_EX_DMG_IMMUNE で、

決定的なのは、静的テーブル（HP/弱点/抵抗/ex/タイプ）が **option 側の導出値
（実効打点・リーサル・プライズ報酬）にしか使われていない**こと。手札トークンは
`_card_token` が zone one-hot と ID を置くだけなので、**「手札にボスの指令がある」ことを
モデルが知る経路は死んだ埋め込みしかない**。

### レポートへの含意（重要）
主張「リストでは差がつかない」には**条件が付く**。我々のエージェントはカードの正体を
ほぼ見ていないため、リスト差を活かす能力に構造的な上限がある。7/31 に見つけた
**「改善方向の効果は基準方策を変えると消えるが、悪化方向は再現する」という非対称性は、
この構造で説明できる**: 枚数配分は「選択肢の出現頻度」を通して効くので悪化は伝わるが、
「このカードは強い」という質的な価値は方策に伝わらない。

## 【重要】評価バグの発覚と再測定 — 2026-08-02 夕
