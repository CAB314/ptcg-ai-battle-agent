# Pokémon TCG AI Battle Challenge — team "cabbage patch"

Code, configuration and trained weights behind our two submitted agents
(`kangaskhan_dh`, rating 993.8 and `hydrapple_k2`, rating 932.6; rank 138 of 6,807
on the Simulation leaderboard), and the analysis behind our Strategy-track writeup.

The writeup itself is `docs/report-draft.md`; every number in it is traced to a source
in `docs/report-numbers.md`; the figures are in `docs/figures/` and are regenerated by
`scripts/make_report_figures.py` from the aggregates in `docs/data/`. The two submitted
deck lists in standard format are `docs/data/decklists/`.

Competition pages: [Simulation](https://www.kaggle.com/competitions/pokemon-tcg-ai-battle) ·
[Strategy](https://www.kaggle.com/competitions/pokemon-tcg-ai-battle-challenge-strategy)
(our writeup appears under team "cabbage patch" once writeups are published).

| Included | Not included (and why) |

| The experiment log (`docs/experiments-log.md`) — dated, including failures | |

## Setup

```bash
# Python 3.12 (pyenv) + poetry; every dependency is pinned in poetry.lock
poetry install

# Competition data (requires accepting the competition rules on Kaggle):
#   engine  -> data/ptcg_engine/ and data/sample_submission/.../cg/
#   cards   -> data/EN_Card_Data.csv
export KAGGLE_CONFIG_DIR=$PWD/.kaggle   # your own kaggle.json
./download_and_unzip.sh

# Static card/attack attribute tables used by the model (regenerate from the engine)
poetry run python scripts/build_vocab.py
```

## Run the submitted agents

```bash
# Play games locally with the exported NumPy policy and measure per-decision latency
poetry run python scripts/bench_inference.py --policy-dir agents/kangaskhan_dh --games 24

# Harness-faithful smoke test of a submission tarball (top-level main.py, no __file__, mirror games)
poetry run python scripts/build_submission.py kangaskhan_dh
poetry run python scripts/tar_smoke_test.py kangaskhan_dh --games 3 --mirror-games 8
```

## Reproduce the training pipeline

1. **Data**: fetch daily public episodes (`scripts/fetch_episodes.py`) and build decision shards
   (`scripts/build_bc_shards.py`). Note the replay `selected` field is shifted by one step; the
   shard builder corrects it.
2. **Behaviour cloning**: `scripts/train_bc.py --config configs/bc_pretrain_v3.json` (all teams pooled,
   2 epochs), then per-deck fine-tuning with `configs/bc_<archetype>.json`.
3. **PPO league**: `scripts/setup_selfplay_run.py` / `scripts/setup_dh_curriculum.py` create a run;
   `scripts/run_actors.py` (28 actor processes) + `scripts/train_ppo.py` (learner) +
   `scripts/ppo_gauntlet.py --loop 3600` (hourly evaluation, best-checkpoint tracking, rollback).
   Hyper-parameters: `configs/ppo_*.json` (KL anchor to the cloned policy, target 0.03; league
   50% mirror / 30% snapshots / 20% frozen; deck mix 55% meta / 25% weak / 20% uniform).
4. **Judge & export**: `scripts/selfplay_judge.py` evaluates the exported NumPy policy through the
   submission code path; `scripts/export_policy.py` refuses to export unless PyTorch and NumPy
   logits agree.
5. **Analysis**: `scripts/field_matchup_matrix.py` (archetype × archetype win rates of other teams'
   agents), `scripts/fetch_our_episodes.py` + `scripts/analyze_final_pair.py` (our ladder games),
   `scripts/meta_timeline.py`, `scripts/clone_winrates.py`, `scripts/deck_ablation.py`.

## Computational requirements (as used)

| Stage | Resources | Time |
|---|---|---|
| Behaviour-cloning pre-train (31.96 M decisions, 2 epochs, batch 512) | 1 GPU (48 GB class), ~200 GB RAM for the in-memory shard store | 1.5 GPU-hours |
| Per-deck fine-tune (5 epochs) | same | minutes per deck |
| One PPO league run (800–1,500 iterations of 49,152 decisions) | 1 GPU + 32 CPU cores, 28 actor processes | 2–4 hours |
| All PPO runs (3 league rounds over 8 archetypes + targeted repairs) | as above | ≈95 GPU-hours |
| Inference (submitted agent) | 1 CPU core, NumPy only | 3.4 ms per decision (mean), 7.4 ms max |

Software: Python 3.12.11, PyTorch for training, NumPy at inference; exact versions in `poetry.lock`.
The engine is a compiled shared library shipped by the competition (x86-64; an ARM64 build is also
provided by the organisers).
